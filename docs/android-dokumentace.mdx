### Účel aplikace

Aplikace pro **skupinové plánování akcí** (svatba, teambuilding, výlet, oslava…).
Organizátor založí akci, pozve účastníky odkazem/QR kódem a k akci si zapne **moduly** —
hlasování, výdaje, chat, program, úkoly, balicí seznam, spolujízdu, ubytování, dárky,
catering a rozpočet. Data jsou v Firebase (Firestore + Auth + Storage + FCM), lokálně
cachovaná v Room a v DataStore.

## 3. Architektura

```
app/src/main/java/com/bettermingle/app/
├── MainActivity.kt              # vstupní bod, locale, deep link e-mail sign-in
├── BetterMingleApp.kt           # Application, init notifikačních kanálů
├── navigation/Navigation.kt     # Routes + NavHost + bottom bar
├── data/
│   ├── model/                   # 16 datových modelů
│   ├── dao/                     # 5 Room DAO
│   ├── database/                # AppDatabase (v6), Converters
│   ├── repository/              # 7 repository (Event, Auth, Chat, Expense, Poll, Room, Carpool)
│   ├── sync/                    # CloudSyncManager, FirestoreSyncService, SyncWorker
│   ├── preferences/             # SettingsManager (DataStore), TierLimits
│   ├── billing/                 # BillingManager
│   └── ads/                     # AdManager
├── ui/
│   ├── theme/                   # Color, Type, Spacing, Shape, Animation, Theme
│   ├── component/               # 17 sdílených komponent
│   └── screen/                  # auth / create / event / home / profile
├── viewmodel/                   # 7 ViewModelů
├── notification/                # kanály, FCM service
├── utils/                       # 14 utilit
└── widget/                      # Glance countdown widget
```

**Datový tok:** UI (Compose) → ViewModel / přímý Firestore přístup → Repository → Room (cache)
+ Firestore (zdroj pravdy). Řada modulových obrazovek čte a zapisuje do Firestore **přímo**,
bez repository vrstvy — je to nekonzistence, kterou by bylo dobré při přepisu sjednotit.

## 6. Obrazovky

### 6.1 Onboarding a autentizace

#### OnboardingScreen
Uvítací sekvence před prvním přihlášením. Po dokončení se do DataStore uloží
`onboardingCompleted = true` a uživatel jde na `login`.

#### LoginScreen
- Přihlášení e-mailem a heslem.
- Google Sign-In přes Credential Manager (s fallbackem na legacy `play-services-auth` na emulátorech).
- Odkazy na registraci, zapomenuté heslo a přihlášení odkazem v e-mailu.

#### RegisterScreen
Registrace e-mail + heslo. Po úspěchu → `profile_setup`.

#### ForgotPasswordScreen
Odeslání resetovacího e-mailu přes Firebase Auth.

#### EmailLinkScreen
Přihlášení bez hesla (magic link). E-mail se ukládá do `SharedPreferences("email_link_auth")`
pod klíč `pending_email`; `MainActivity.handleEmailSignInLink()` pak dokončí přihlášení
při návratu z odkazu.

#### ProfileSetupScreen
Doplnění jména a výběr avatara po prvním přihlášení. Nastavuje
`profile_setup_completed` v DataStore.

### 6.4 Dashboard akce (`EventDashboardScreen`, 1336 řádků)

Nejdůležitější obrazovka. Odpovídá screenshotům 1 a 19.

#### Top bar
- Zpět (šipka), název akce s emoji.
- Akce vpravo: **ikona dokumentu** (export PDF), **sdílet**, **kalendář** (přidat do kalendáře),
  **tři tečky** (overflow menu).

#### Tělo
1. **Popis akce** (`Náš velký den!`) — podporuje jednoduchý markdown (`parseSimpleMarkdown`).
2. **Countdown karta** — plná `PrimaryBlue`, zaoblení 24 dp:
   - název akce nahoře uprostřed (bílý, menší),
   - 4 bloky oddělené dvojtečkou: **dní : hodin : minut : sekund**,
   - každý blok je poloprůhledný obdélník s velkým tučným číslem a popiskem pod ním,
   - blok sekund má **zlatý (`AccentGold`) obrys** a při každé změně animuje.
3. **Sekce „Moduly"** v šedém kontejneru:
   - Coach mark `dashboard_modules` s ikonou žárovky a textem
     „Klepni na modul pro vstup. Organizátoři mohou podržet pro přesunutí a přidávat nebo
     odebírat moduly." + „Rozumím".
   - **Mřížka 3 sloupce** dlaždic modulů.

#### Dlaždice modulu (`FeatureModuleCard`)
- Pastelové pozadí odvozené z barvy modulu (`pastelForColor`).
- Uprostřed nahoře kruh v bílé/světlé barvě s ikonou v sytém odstínu.
- Pod ním název modulu tučně.
- Volitelný podtitulek s počtem (např. „3 aktivní", celková částka výdajů).
- **Badge** s počtem nových položek od posledního zobrazení.
- **Drag & drop** pro organizátora — pořadí se ukládá do `enabledModules`.
- Dlouhé podržení → možnost odebrat modul.

**Algoritmus vyrovnání dluhů** (`DebtCalculator.calculateMinimumTransactions`):
1. `balance[user] = zaplaceno − dlužno`
2. věřitelé (`> 0.01`) sestupně, dlužníci (`< −0.01`) sestupně dle absolutní hodnoty
3. greedy párování — vždy `min(věřitel, dlužník)`, zaokrouhleno na 2 desetinná místa
4. výsledek = seznam `Debt(fromUserId, toUserId, amount)`

`equalSplit(total, count)` dělí rovným dílem se zaokrouhlením na haléře.

**Měny:** `CZK` (výchozí, `NumberFormat` cs-CZ), `EUR`, `USD`, `GBP`, jinak `"%.2f %s"`.
`formatCzkShort` zkracuje na „tis. Kč" / „mil. Kč".

```
  ├── ratings/{userId}             overallRating, organizationRating,
  │                                atmosphereRating, venueRating, comment, createdAt
  ├── activity/{activityId}        actorId, actorName, type, description,
  │                                timestamp, readBy[]
  └── lastSeen/{userId}            { voting: ts, expenses: ts, chat: ts, … }

joinRequests/{requestId}
  userId, eventId, status
```

**Invite kód:** 6 znaků z `A–Z0–9`, generovaný lokálně (`EventRepository.generateInviteCode`).

### 7.4 Synchronizace

`EventRepository.syncFromCloud()`:
1. Načte akce, kde `createdBy == uid`.
2. Přes **collection group query** na `participants` s `userId == uid` najde akce,
   kde je uživatel účastník, a dotáhne je.
3. Smaže lokální akce, které už v cloudu nejsou.

Zápisy jdou `SetOptions.merge()`. Mazání akce načte 11 subkolekcí paralelně
a maže po dávkách po 500 dokumentech.

Doplňkově: `CloudSyncManager`, `FirestoreSyncService`, `SyncWorker` (WorkManager).

## 8. Bezpečnostní pravidla Firestore

Soubor `firestore.rules`. Klíčové helper funkce:

```js
isEventParticipant(eventId)  // existuje participants/{uid} NEBO createdBy == uid
isEventOrganizer(eventId)    // createdBy == uid
isSecurityEnabled(eventId)
requiresApproval(eventId)
hidesFinancials(eventId)     // securityEnabled && hideFinancials
```

| Cesta | Read | Write |
| --- | --- | --- |
| `users/{uid}` | každý přihlášený | jen vlastník |
| `events/{id}` | tvůrce nebo účastník | create: každý přihlášený; update/delete: organizátor |
| `…/participants/{id}` | účastník nebo vlastní záznam | create: manuální hosty jen organizátor; jinak pokud není vyžadováno schválení; update/delete: organizátor nebo vlastní záznam |
| `…/polls/{id}` | účastník | create: účastník; update/delete: organizátor nebo autor |
| `…/polls/…/options/…/votes` | účastník | účastník |
| `…/expenses/{id}` | účastník, **a pokud `hideFinancials`, tak jen organizátor nebo plátce** | create: účastník; update/delete: organizátor nebo plátce |
| `…/budgetCategories/{id}` | účastník | jen organizátor (položky uvnitř může přidat účastník) |
| ostatní subkolekce | účastník | účastník |
| collection group `participants` | jen vlastní záznamy | — |
| `joinRequests/{id}` | žadatel nebo organizátor | create: žadatel; update: organizátor |

## 17. Poznámky k migraci na Expo

Body, které při přepisu vyžadují rozhodnutí:

1. **Přímé Firestore volání v UI.** Většina modulových obrazovek čte a zapisuje do
   Firestore přímo z composable. Při přepisu doporučuji sjednotit do zustand store /
   service vrstvy — jinak se nekonzistence přenese.
2. **Room → co s lokální cache.** Buď `expo-sqlite`, nebo se spolehnout na
   offline persistenci Firestore SDK (jednodušší, doporučeno).
3. **Billing → RevenueCat.** Lucciola už RevenueCat používá; sjednocení ušetří práci.
   Produkty a ceny je nutné namapovat na RevenueCat entitlements.
4. **Glance widget** nemá v Expo přímý ekvivalent — buď nativní modul, nebo odložit.
5. **PDF export** — `EventPdfGenerator` je 614 řádků nativního kreslení na canvas.
   V RN se nabízí `expo-print` s HTML šablonou, což znamená přepsat layout od nuly.
6. **Lokalizace** — 1046 klíčů × 6 jazyků; export z `strings.xml` do JSON se dá skriptovat.
7. **Vektorové ilustrace** — 19 XML drawable → SVG.
8. **`FLAG_SECURE`** — v Expo přes `expo-screen-capture`.
9. **Per-app jazyk** — `AppCompatDelegate.setApplicationLocales` nemá RN ekvivalent;
   řeší se vlastním i18n stavem, ale ztratí se systémová integrace v nastavení Androidu.
10. **Cloud Functions a Firestore rules zůstávají beze změny** — backend se nemigruje.
